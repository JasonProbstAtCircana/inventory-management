System Overview

Two independently-run processes. The browser talks to the API directly across origins — there is no Vite dev proxy and no reverse proxy, so CORS is what makes the system work at all.

What the system does

  • Tracks inventory across three warehouses and five product categories
  • Manages a year of orders through four lifecycle states
  • Surfaces demand forecasts, backlog pressure and spending analytics
  • Applies one global four-axis filter consistently across every screen
  • Renders fully in English or Japanese, with currency following the locale

What it deliberately is not

  • No database — JSON files are read once at import and held in module globals
  • No writes — every implemented endpoint is a GET
  • No real authentication — useAuth hardcodes a signed-in user
  • No server-side state — nothing a user does survives a page reload
  • No frontend test suite — tests cover the API only

Data Flow

The full path of one filter change, from the select element to the re-rendered table. This loop is the spine of the whole application.

  1. components/FilterBar.vue User changes a filter

    Four <select> elements are v-model-bound to refs imported from useFilters() — period, warehouse, category and status.

  2. composables/useFilters.js Singleton state updates app-wide

    The refs live at module scope, outside the exported function, so every component that calls useFilters() receives the same ref instances. This is the app's global store — there is no Vuex or Pinia.

  3. views/*.vue A watcher in the active view fires

    Each view watches only the filters it honours. Inventory.vue watches location and category; order-driven views also watch status and period. The watcher calls the view's loader.

  4. useFilters.getCurrentFilters() UI names are mapped to API names

    selectedLocation becomes warehouse and selectedPeriod becomes month. The period key is omitted entirely when set to all.

  5. api.js Query string is assembled

    Each method builds a URLSearchParams and skips any value equal to 'all', so a default filter contributes no parameter. Axios issues the GET against http://localhost:8001/api.

  6. server/main.py Server filters the in-memory lists

    apply_filters() matches warehouse exactly but compares category and status case-insensitively — which is why the UI sends lowercase category values like circuit boards. filter_by_month() then does a substring match against order_date, expanding Q1-2025-style keys through QUARTER_MAP.

  7. Pydantic response_model Response is validated and serialised

    Endpoints declaring a response_model coerce and strip the dictionaries to the declared shape. A field added to the JSON but not to the model is silently dropped from the response.

  8. views/*.vue Raw data lands in a ref, derived data in computeds

    The response is assigned to a raw ref such as items or allOrders. Everything downstream — the search box, sorting, stock-status classes, totals — is a computed over that ref. Server filtering is coarse; client computeds do the fine-grained work.

  9. useI18n + utils/currency.js Presentation is localised at render time

    Templates call t() for copy and formatCurrency() for money. Locale drives currency automatically: en renders USD, ja converts at a hardcoded rate of 150 and renders JPY.

Low stock is a derived concept, computed in two places

The server counts an item as low stock when quantity_on_hand <= reorder_point. The Inventory view independently adds a middle "warning" band at reorder_point * 1.5 for its status colouring. The two rules are related but not identical, and neither is stored.

Conventions Worth Knowing

Recurring decisions that explain why the code looks the way it does.

Singleton composables as the store

Refs are declared at module scope in useFilters.js and useI18n.js, so all callers share one instance. Cheap and effective — but it means state is global and survives route changes, and any component can mutate it.

Raw refs in, computed properties out

Server responses go into plain refs; every derived value is a computed. Views never mutate fetched data in place, which keeps re-renders predictable.

Two-stage filtering

The server handles the four coarse dimensions. Free-text search, sorting and thresholds run client-side over the already-fetched list — no round trip while typing.

Case-insensitive matching by convention

The API lowercases both sides for category and status, so the UI can send circuit boards while the data stores Circuit Boards. Warehouse is the exception and must match exactly.

Locale drives currency

Switching to Japanese does more than swap strings: it re-renders money as JPY, converts at a fixed rate, and changes the mock user's name and job title.

Failures degrade quietly

Task calls in App.vue are wrapped in try/catch that only console.errors. The missing endpoints therefore produce no visible error — the UI simply shows the mock tasks alone.

Known Gaps and Loose Ends

Observations from reading the source. These are stated as findings, not recommendations — several are reasonable for a workshop demo.

The task feature is half-built

App.vue merges four hardcoded mock tasks from useAuth with tasks fetched from /api/tasks, which does not exist. Mock tasks can be toggled and deleted in memory; anything routed to the API silently fails. Deleting a mock task also mutates the currentUser computed's array directly.

client/src/App.vue:84-147 · client/src/composables/useAuth.js:26-84

Purchase orders are modelled but unreachable

PurchaseOrder and CreatePurchaseOrderRequest are fully defined in main.py and never referenced by a route. The client has two matching methods that nothing calls. The only live use of the fixture is the has_purchase_order flag on /api/backlog — and since the file is an empty array, that flag is always false.

server/main.py:104-121 · client/src/api.js:97-105

views/Backlog.vue is orphaned

A complete 152-line view that no router entry references and no component imports. Backlog data reaches the UI only through BacklogDetailModal.vue, opened from the dashboard.

client/src/main.js:13-20

Quarter filtering exists only on the server

QUARTER_MAP and the Q-prefix branch in filter_by_month() handle Q1-2025 through Q4-2025, but FilterBar.vue offers only individual months. The capability is reachable by hand-crafting a request, never through the UI.

server/main.py:10-31 · client/src/components/FilterBar.vue:8-20

CORS is wide open alongside credentials

The middleware sets allow_origins=["*"] together with allow_credentials=True, plus all methods and headers. Convenient for a local demo, and an invalid combination to carry into anything deployed.

server/main.py:50-56

Duplicated quarter logic

/api/reports/quarterly re-derives quarters with a hand-written if/elif chain over date substrings rather than reusing QUARTER_MAP directly above it. Two encodings of the same calendar.

server/main.py:239-248

Test coverage is backend-only and read-shaped

40 tests across dashboard, inventory and miscellaneous endpoints. There are no frontend tests, and no test asserts the absence of the six unimplemented routes.

Startup scripts are POSIX-only

scripts/start.sh and stop.sh assume macOS or Linux. On Windows the two servers must be started manually, as the README notes.
